## Design decisions
1. Settings UI = gear button (`#btn-settings`) in the header next to `#btn-minimize`, opening a small in-overlay popover `#settings-pop` (not native, so it stays content-protected). Fits best because the header is visible on every tab and the Answer tab is already crowded.
2. Localstorage key `captureMode` with values `'ocr'` (default) | `'vision'`. IPC channel `set-capture-mode`, mirrored from `set-tone`; main holds `let captureMode = 'ocr'`. Strict whitelist in main (`'ocr'|'vision'`), anything else ignored, so the default path can't be broken.
3. Batch logic lives in a new UMD-style file `overlay_app/vision-batch.js` (pure functions, no DOM) loaded by index.html via `<script src="vision-batch.js">` and by node via `require`. Single source of truth, testable.
4. New IPC event `vision-capture` (main -> renderer), payload `{ dataUrl, sourceType }`. Main restores the window itself (show + expand), and the renderer also expands from the dot (belt and braces, because only the renderer knows the dot class state).
5. Region vs full: pass the real `source_type` per image; the record's `source_type` is `'screenshot-region'` if every image is region, else `'screenshot-full'`. Request field is an optional `source_types` list (same length as `images`); if absent/invalid default to `'screenshot-full'`.
6. Size handling: renderer cap of 6 images (`MAX_BATCH = 6` in vision-batch.js); backend `VISION_MAX_IMAGES` (env `VISION_MAX_IMAGES`, default 6) and `VISION_MAX_IMAGE_BYTES` per decoded image (env, default 15 MB) -> 413. Server downscales longest side to `VISION_MAX_SIDE` (env `VISION_MAX_SIDE`, default 2000) and re-encodes as PNG (keep PNG for text sharpness); saved file is the downscaled one (also keeps disk small).
7. Status codes: 400 invalid payload/mode/images/data URL; 413 too many images or an oversized image; 503 `ai_helper is None`/`db_layer is None`; 502 for `AIError`. Unexpected exceptions -> 500 JSON with a generic message (log the stack server-side with `log`/`logging`, never return it).
8. Persistence ordering: call OpenAI FIRST, then save files + create the record only on success (so a failed/retried send doesn't leave orphan 'captured' records). Images are validated/downscaled in memory before the call.
