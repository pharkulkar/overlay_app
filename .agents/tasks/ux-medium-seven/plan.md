## Decisions (with reason)

1. Status line = ONE body-level `<div id="status-line" role="status" aria-live="polite">` placed immediately AFTER `#overlay-card`, `position:fixed; z-index:2500; pointer-events:none`, plus an empty reserved `<div class="status-slot">` in the card under the header. Reason: only a body-level element can sit above `#edit-modal`; the slot keeps layout stable. Position is deterministic through two CSS vars (`--hdr-h`, `--status-h`) used by header height, slot height and the line's `top`. `#overlay-card.hidden + #status-line {display:none}` hides it in compact mode.
2. Modal gets `padding-top` so `#edit-card` starts below the status line (otherwise the card at `90vh` max-height overlaps it).
3. The modal's inner `setStatus` is DELETED. Its ~30 call sites then resolve to the outer `setStatus(label, state)`. Outer is changed so the header dot only changes when `state` is passed. `#edit-status` span, its CSS, `statusEl`, dead `showBusy`, and the popout fallback write to it are removed (redundant, verified safe). Auto-clear (about 6 s) only when `state` is `'ok'` or `'idle'` and text is non-empty; `'error'`, `'thinking'` and no-state messages stay until replaced.
4. `#answer-status` becomes a static "Answer" zone label (drop its id and the `answerStatus` const/write). Generic labels fed to `setStatus` that only made sense as a section label are fixed at their call sites: `setStatus('Answer','idle')` -> `setStatus('', 'idle')`; `setStatus('Answer','ok')` -> `'Answer ready'`; `'Answer (cached)'` and `'Answer — no API key'` -> drop the "Answer" prefix (`'Cached answer'`, `'No OpenAI key set'`).
5. `showCaptureError` calls `setStatus(msg, 'error')` instead of `'Capture failed'` so hotkey failures (sent as `capture-error` from main.js `registerHotkey` failures) show in the line; the `answerBody.textContent = msg` and `showView('answer')` stay as today.
6. Edit modal sticky bar via `position: sticky; bottom: 0` inside the existing scroll container `#edit-body`, with `#edit-image-tools { display: contents }` so the bar's containing block is `#edit-body` (the `.hidden` rule still wins because it is `!important`). Convert `<fieldset id="edit-vision-box">` to a `<div>` (fieldset + sticky is fragile) and move `#edit-add-shot` into it; make the Get Answer `.actions` row sticky the same way. Zero change to JS toggling logic apart from hiding `#edit-add-shot` when not in fresh mode.
7. Pause/Resume: keep id `iv-pause` for the single toggle, DELETE `#iv-resume` and `el.resume`. Label and `data-tip` switch in `setControls()`.
8. Tone moves into Setup. Answer tab loses its visible tone control; it still reads `toneSelect.value` (same id, same const). Report this to the user as a visible behaviour change.
9. Opacity control lives in the header (global setting, not Interview-only). Persist key `overlayOpacity`. Applied at the top of script B (script B runs before first paint on a local file load; no extra head script).
10. First-run checks: new read-only IPC `get-permissions` (main) + ONE preload line. Pure mapping helper in `ux-helpers.js` so it is testable. Backend row reuses the existing `checkBackend()` health call (no extra fetch). Hotkey row copies `#hotkey-strip` text (no duplicated strings).
11. No FEAT decomposition / no workflow restructure: all seven items edit the same `index.html` regions (M2 and M3 both touch the modal, M1 and M6 both the tabs and the Interview toolbar), so one coder working sequentially is safer than splitting. The existing implement-and-review loop runs this plan unchanged.
